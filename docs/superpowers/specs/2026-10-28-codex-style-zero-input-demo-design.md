# Codex 式零输入管束 Agent Demo 设计

## 意图

管束 Agent 是整个设计流程中的中间环节。普通设计人员不应再输入设备位号、产品型式、DN 或文件路径；只需点击“开始管束设计”，然后查看预览、修改参数、审核并确认。界面要像用户给出的 Codex 截图，宽敞、左侧导航、右侧对话与变更预览为主。

## 界面

- 窗口默认 `1760×1040`，启动后最大化，最小不小于 `1280×760`。
- 左侧固定约 `300 px`，只放：“管束 AI”、“开始管束设计”、“AI 设置”、“历史方案”和四阶段进度。
- 右侧主区是单一对话界面：顶部标题，中间对话，需要审核时出现的参数预览卡，底部输入框与发送按钮。
- 审核预览不再作为右侧狭抽屉，而是占满主区宽度的内嵌卡片；表格、错误、推荐值、重审和确认全在这张卡片中。
- 不显示“演示库”、文件数、设备位号、产品型式、DN 或长段说明文字。

## 交互

1. 用户点击左侧“开始管束设计”。
2. Demo 在后台用内置模拟数据执行“读数据库→获取上游数据→历史建议→生成预览”，界面不暴露这些模拟输入控件。
3. 预览卡出现，用户只能在预览表中改参数，并按现有四阶段流程审核。
4. 用户可随时在底部输入要求。当文本包含当前阶段可编辑参数名和数值时，Agent 直接修改预览并撤销已通过状态；其他要求作为本次设计备注。

## 方案

采用唯一符合现有工程的方案：在 PyQt5 `QMainWindow` 内使用水平布局划分左侧栏和右主区，复用已有 `ReviewSession`、参数表和规则校验。不另做 Web/Electron 前端，因为会重写所有审核控件且不利于快速演示；不保留独立审核抽屉，因为它已经被用户明确否定。用户给出的截图和“完全一样”要求即为对该方案的选择。

## 边界

- 只修改独立 Demo，不改 `DongLanpec` 交付工程。
- 模拟数据仅用于 Demo，不在界面伪装成真实生产数据。
- 保留当前错误标红、推荐值、重新审核、用户确认和演示数据库事务逻辑。

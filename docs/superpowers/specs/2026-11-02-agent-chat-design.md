# 管束 Agent 对话式交互设计

## 目的

把 Demo 从“参数审核页附带一个输入框”改成“聊天为主、预览按需出现”的管束 Agent。设计人员可以直接用自然语言补充或修改要求，不需要记参数表位置，也不需要理解 JSON、API 或数据库。

## 已选方案

采用受控结构化对话方案。DeepSeek 每次返回两部分：给用户看的中文回复，以及零到多个结构化参数修改动作。程序只接受四个管束阶段的规范参数名，并再次检查字段是否存在、是否允许人工修改；模型不能执行 SQL、不能确认审核、不能跳过“保留”。

未采用纯聊天文本方案，因为无法可靠落到参数草稿；未采用让模型直接调用数据库或界面工具的方案，因为会绕过现有联动、审核和版本控制。

## 交互

- 默认界面参考用户提供的“管口定义 Agent”：左侧新建对话与历史对话，中间为聊天记录，底部输入框。
- 点击“开始管束设计”后，Agent 在后台装载模拟数据并生成四阶段草稿；参数预览默认收起。
- 用户可正常提问，也可说“换热管中心距改成 34”“旁路挡板数量改为 3”“管板厚度改成 65”。
- 当前阶段或后续阶段的可编辑参数立即写入内存草稿。修改后 Agent 在聊天中列出“阶段 / 参数 / 原值 → 新值”。
- 修改后续阶段不会跳过当前阶段，也不会提前入库；到达该阶段后仍需人工查看、校验并点击“保留”。
- 修改已经审核过的阶段时，撤销该阶段及其后续阶段的确认，并返回最早受影响阶段。
- 只读、联动计算、未知参数或非法动作拒绝执行，并在回复中说明原因。
- 没有 API Key 时保留本地基础指令解析；不能识别时明确提示需要配置 DeepSeek，而不是假装 AI 已理解。

## API 协议

请求只包含最近的有限条聊天、四阶段参数摘要、当前阶段和用户本次消息。模型返回 JSON：

- `reply`: 面向设计人员的简短中文回复；
- `actions`: 数组，每项包含 `stage`、`parameter`、`value`。

返回结果经过白名单解析，未知阶段、未知字段、重复动作和超量动作被拒绝。API 请求在后台线程中执行，界面不能卡死。

## 数据与安全边界

- 对话修改只进入 `ReviewSession` 内存草稿。
- 只有现有“保留”按钮通过本地规则校验并获得用户确认后才能写入独立演示数据库。
- API Key 继续使用现有设置与 Windows 加密保存方式。
- 不修改正式 `DongLanpec`，不连接生产数据库。

## 验收

- API 可把跨阶段自然语言请求解析为结构化动作。
- 后续阶段草稿立即修改，但当前审核顺序不跳跃。
- 只读字段和未知字段无法修改。
- 聊天回复显示成功和拒绝项；修改后可打开对应预览。
- 无 Key 的基础数值指令仍可使用；无法识别时给出真实提示。
- 完整自动测试、启动器测试和编译检查通过。

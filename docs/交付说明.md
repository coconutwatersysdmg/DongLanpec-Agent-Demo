# 管束设计 Agent Demo · 交付说明

本文件对应需求中的“交付内容”：修改文件清单、运行方法、API Key 配置方法、使用操作手册、
从启动到最终保存的演示步骤、已验证/未验证项目、真实数据库连接失败的排查方法。

---

## 1. 交付范围与原则

| 原则 | 落实情况 |
| --- | --- |
| 只在 Demo 目录内改动 | 所有新增/修改都在 `DongLanpec-Agent-Demo/` 内；正式项目仅被**读取**（源码参考、静态资源复制、数据库查询） |
| 不通过导入正式项目运行 | `bundle/` 是重构后的独立实现，`import` 关系不指向 `DongLanpec` |
| 四大 Tab 沿用正式命名 | `models.STAGES = ("管板型式", "布管", "管-板连接", "轴向设计")` |
| 使用真实数据库 | `db/production.py` 只连正式 MySQL（`产品设计活动库`/`元件库`/`配置库`），失败直接报错，不回退模拟库 |
| 真实布管计算 | `bundle/engine.py` 通过 pythonnet 调正式 `HE3DTB.dll`（`LayoutTubeCalculate`），管孔坐标与关键尺寸全部来自正式组件 |
| 图形与表格真实联动 | 选中/框选/删除/撤销/元件布置都会重算 `removed`/`components`，同时刷新场景与右侧数量表，并进入写库 payload |

## 3. 运行方法

```bash
cd DongLanpec-Agent-Demo
python -m pip install -r requirements.txt      # PyQt5 / PyMySQL / pythonnet / openpyxl
python main.py                                  # 正常启动
```

也可双击 `启动管束设计助手.cmd`（可用环境变量 `DONG_LANPEC_PYTHON` 指定解释器）。

验收留证用的离屏截图：

```bash
python main.py --screenshot artifacts/stage1.png --stage 1
python main.py --screenshot artifacts/stage3.png --stage 3 --product PD2026110422462701
```

`--stage` 取 0..3，会自动依次“保留”前面的 Tab；截图模式**只生成写库计划，绝不写库**。

## 4. API Key 配置方法

三种方式，任选其一：

1. **环境变量**（推荐，仅本次运行有效）
   ```bash
   set DEEPSEEK_API_KEY=sk-xxxx          # Windows cmd
   $env:DEEPSEEK_API_KEY="sk-xxxx"       # PowerShell
   ```
   也支持 `DONG_LANPEC_AI_API_KEY`。

2. **界面设置**：左下角 **AI 设置** → 填 Key → 不勾选“记住”则仅本次运行有效；勾选“记住”会用当前 Windows
   账户的 DPAPI 加密保存到 `%APPDATA%\DongLanpecAgentDemo\settings.json`（文件内无明文）。

3. **不配置 Key**：程序进入离线规则模式，仍可完整演示“读库 → 四 Tab 草稿 → 图形/表格操作 → 保留 → 写库计划”，
   并明确提示需要 Key 才能自由问答。

默认模型 `deepseek-v4-flash`，服务地址 `https://api.deepseek.com`。Key 不写入代码、不写入日志；
`deepseek.log` 只记录请求/响应摘要与 HTTP 错误码。

## 5. 使用操作手册

### 5.1 启动与读取前序数据

1. 点 **开始管束设计**。
2. 程序读取：产品记录 → 前序模块已保存参数（设计数据表/通用数据表）→ 布管参数表已有值 → 该产品型式的正式默认表补齐 → 管板形式表。
3. 顶部标题显示 `产品ID · 产品型式 · DN`，聊天区列出本次数据来源。

### 5.2 管板型式（Tab 1）

- 参数：产品型式、公称直径 DN（只读，来自前序）、管板类型 a–f、R1/R2/h/α/ρ/e、布管限定圆 DL（只读联动）。
- 右侧：只显示 `元件库.管板形式表` 对应的形式示意图（与正式程序一致，不再额外画结构圆）。
- 修改 R2 → DL 自动重算；点 **保留** 后进入布管。

### 5.3 布管（Tab 2）

- 左：65 项参数表。控件类型与正式程序一致：普通下拉不可输入、可输入下拉只能填“程序推荐”或数字、只读参数不可改。
- 中：布管图形（外圆 DN、内圆 Dis、限定圆 DL、分程隔板带、换热管孔、圆心连线、
  0/90/180/270° 中心线与方向标记）+
  12 个元件按钮（换热管/拉杆/自由拉杆/中间挡管/旁路挡板/滑道/吊环螺钉/中间挡板/防冲板/折流板/径向开孔/删除）+
  布管/撤销/重绘/全屏。
- 右：管孔数量分布表（按行/按列切换、总孔数、整行选中、多行选中、当前选中换热管数）。
- 交互：
  - 点表格某行 → 该行淡蓝高亮，图形中同一行的换热管同步高亮，底部显示“已选中 N 个管孔”；
  - **Ctrl 点选 / Shift 连选可同时选中多行**，多行对应的管孔一起高亮、数量合并统计；
  - 左键拖动框选 / 点击单根管孔 → 表格对应行同步高亮（Ctrl 追加）；
  - 选中后点元件按钮 → 生成元件并占用管孔，图形、数量表、总孔数立即刷新；
  - **删除**移除选中管孔或已选元件；**撤销**回退上一步（最多 30 步）；
  - 改参数（如中心距 34）→ 重新布管，图形与数量表一起刷新；
  - 底部状态提示只保留最新一条（连续选行/连续布置元件不会把聊天区刷满），
    失败、冲突等错误仍单独追加一条不会被覆盖。
- 自然语言（离线也可用）：换热管中心距改成34毫米 / 至少布置500根换热管 / 重新布管尽量多布 /
  外围对称布置8根拉杆 / 增加两块旁路挡板 / 在上方布置防冲板 / 把刚才的修改撤销 /
  为什么这个参数不通过 / 使用推荐值 / 保留当前方案。

### 5.4 管-板连接（Tab 3）

- 连接方式（5 种）× 管板类型（0 整体 / 1 复合），参数按 `元件库.管板连接表` 装载。
- 右侧：正式程序焊缝/管板示意图 + 管孔连接剖面简图（A/B/L 标注）。

### 5.5 轴向设计（Tab 4）

- 换热管公称长度 LN 由布管页联动（只读）；折流板间距、首末板距离、板厚可改。
- 右侧：轴向剖面草图（两端管板、换热管、交替折流板、LN 与间距标注、折流板块数）。

### 5.6 保留与写库

1. 每个 Tab 底部只有一个 **保留**。
2. 点击时先跑参数校验 + 联动校验 + 几何干涉检查；不通过则参数标红、给出原因与推荐值，**不写库**、不能进入下一页。
3. 通过后弹窗确认；确认后保留当前页并自动进入下一 Tab。
4. 从左侧可回到已保留的 Tab 修改；一旦修改，后续 Tab 草稿自动作废并提示重算。
5. 四个 Tab 全部保留后弹窗列出写库计划（表名与 SQL 条数），确认后由 `ProductionRepository.save_design`
   在**单个事务**内执行，失败自动回滚并给出错误。

## 9. 数据库连接失败排查

程序不会悄悄退回模拟库；失败时会直接显示错误。常见原因与处理：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Can't connect to MySQL server on 'localhost' (10061)` | MySQL 未启动或端口被改 | 启动 MySQL 服务；确认监听 3306；必要时设置 `DONGLANPEC_DB_PORT` |
| `Access denied for user 'root'@'localhost'` | 账号/密码不对 | 与正式程序 `modules/buguan/buguan_ziyong/database_utils.py` 保持一致（默认 root/123456），或用 `DONGLANPEC_DB_USER` / `DONGLANPEC_DB_PASSWORD` 覆盖 |
| `Unknown database '产品设计活动库'` | 库未导入或库名不同 | 用正式程序安装库；或设置 `DONGLANPEC_DB_NAME` |
| `Unknown column '管板型式ID'` 等 | 库结构与正式程序版本不一致 | 使用正式程序同版本的数据库脚本；不要手工改表 |
| 启动后提示“正式数据库里还没有产品记录” | 业务库为空 | 先在正式程序里创建产品并保存前序模块数据 |
| 写库失败并回滚 | 表结构/权限/外键 | 看聊天区的错误原文；确认账号对相关 `产品设计活动表_*` 有 INSERT/DELETE 权限 |

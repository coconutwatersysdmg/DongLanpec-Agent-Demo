## 1. 调研结论

### 1.1 原程序的真实数据来源

管束模块不是让用户从零输入全部参数。`My_Piping.py` 的现有逻辑按以下优先级装载数据：

1. 当前产品已保存的布管参数、管板形式、管板连接和轴向设计数据；
2. 前面模块保存在 `产品设计活动库` 中的设计数据、通用数据和元件附加参数；
3. `元件库` 中按产品型式区分的 U 形管或浮头式默认参数；
4. 用户在当前管束模块中的人工修改。

因此，AI 不应重新生成整张左侧参数表。Demo 先按原有读取优先级构造“基础值”，AI 只从文件中提取可能影响设计的要求并形成候选修改。生产代码的装载函数带有清空旧布管结果等副作用，Demo 不能直接调用它；本次只复用查询含义、字段映射、默认值优先级和纯校验规则。

### 1.2 四个审核阶段

| 阶段 | 原程序数据 | AI 主要关注 | 人工可修改内容 |
|---|---|---|---|
| 管板型式 | 产品型式、DN、管板类型及节点参数 | 文件中明确的管板型式或特殊结构要求 | 管板节点参数、布管限定圆 DL 等 |
| 布管与元件 | 布管参数默认表、上游设计数据、已保存元件 | 管程分程、隔板相邻管中心距、拉杆、旁路挡板、防冲板、折流板/支持板要求 | 全部布管参数和元件建议 |
| 管-板连接 | 已保存连接数据或元件库默认连接 | 强度焊/贴胀、先胀后焊、焊接形式等 | 连接形式和焊接结构参数 |
| 轴向设计 | 换热管和元件轴向信息 | 管长、伸出长度、元件间距/厚度等 | 换热管与元件轴向表 |

原程序中的关键联动必须在人工修改后再次计算或校验：管板节点参数对 DL 的影响、管径/壁厚/管心距关系、管程与分程形式的合法组合、焊接长度与管板厚度约束、伸出长度与换热管长度约束，以及下游阶段对上游参数的依赖。

### 1.3 输入文件筛选结果

样例压缩包共 28 个文件：16 个 PDF、10 个 XLSX、2 个旧版 DOC。当前运行环境可读取 PDF 和 XLSX；旧版二进制 DOC 在转换前只显示“未解析”，不会把乱码或字节片段当成事实。

样例中存在以下风险，决定了必须以“设备位号 + 证据 + 人工审核”为核心：

- 同一个包包含多台设备，不能把别的设备参数合并进当前设计；
- 数据表、问题单、澄清和后续批准回复并存，问题句不等于设计结论；
- 同一设备可能存在版本变更，例如浮头式改为 U 形管；
- “U 形管根数”和“管孔数”口径不同，不能直接覆盖；
- 文件未给出元件布置时，可参考同型式、同 DN 的历史方案，但必须标为“历史建议值”，不能伪装成文件事实。

样例中对管束模块有直接价值的材料包括：换热器数据表、设备请购文件、项目记录/联络答复、材料表和审图意见。保温、防火、涂漆等文件保留在来源清单，但默认不送入管束参数提取。

样例包不设置一份人为编造的“唯一参数标准答案”，而采用可复查的分类验收：应识别多台 `OST-*` 设备；选择某设备后只返回包含该设备或明确通用要求的证据；问题句进入待确认；后续批准回复与早期数据不一致时进入冲突；U 形管根数和管孔数保持两个字段。内置验收重点覆盖 `OST-E-1903A/B` 与 `OST-E-1904A/B` 的设备隔离和数量口径，不自动替用户裁决哪个版本最终有效。

## 2. 产品方案

### 2.1 单窗口交互

界面只保留一个类似 Codex 的互动窗口，不再显示布管图，也不复制原软件的四个标签页。默认只显示对话和底部输入区，Demo 用的资料、设备、产品型式和 DN 入口也收敛在输入区。只有当 Agent 已经准备好待审核数据时，右侧才展开可编辑的审核抽屉；用户可随时收起，并通过顶部“查看审核”重新打开。

Demo 中的“添加输入资料”只是为了给老师独立演示完整闭环。正式软件的资料已在“条件输入”阶段处理，管束模块只接收总 Agent/数据空间流转的数据，并从数据库读取前置模块参数。

最短操作路径：

1. 用户选择一个或多个 PDF/XLSX/DOC/ZIP，或点击“使用示例输入包”；
2. 程序扫描文件并列出识别到的设备位号，用户只需选择当前设备；
3. 模拟上游总 Agent 把该设备和相关文件路由给管束 Agent；
4. 管束 Agent 读取基础参数，检索当前设备证据，提取候选修改，查历史建议并运行校验；
5. 用户逐阶段审核，可直接在表格中改单元格；每次修改立即使本阶段变为“待审核”，并撤销旧的审核通过状态；
6. 用户点击“审核本阶段”后运行全部联动和规则检查。不通过的单元格标红，旁边显示错误原因和推荐修改值，并可点击“一键采用推荐值”；
7. 采用推荐值或手工修改后必须再次审核，直到所有检查全部通过；
8. 规则审核通过只代表“可以确认”，不会自动进入下一阶段。用户仍需点击“确认并下一步”，此时才把本阶段审核快照写入独立 SQLite；
9. 四个阶段均通过规则审核并由用户确认后，最终状态改为完成；
10. 保存成功显示设计编号和版本，可从历史记录重新打开，不接触生产库。

### 2.2 AI Agent 在哪里

这个 Demo 不是单次“文本转 JSON”。管束 Agent 维护一个有状态任务，并按需要调用受控工具：

- `scan_documents`：扫描可解析文件和页/工作表；
- `identify_equipment`：识别设备候选并让用户确认；
- `load_base_parameters`：按原程序优先级读取模拟上游值和默认值；
- `retrieve_evidence`：只检索当前设备与管束关键词相关片段；
- `extract_document_facts`：调用 DeepSeek，把片段转换为带证据的候选事实；
- `lookup_similar_history`：文件缺失时查同型式、同 DN 的历史建议；
- `validate_stage`：执行确定性的参数联动和校验；
- `prepare_review`：生成当前阶段差异预览；
- `commit_reviewed_design`：只有用户审核通过后才能调用，并写独立演示库。

模型不能执行任意 SQL、不能自己批准、不能绕过校验、不能写生产库。界面会把每一步工具调用和结果用普通中文展示，所以用户能看见 Agent 做了什么，而不是只看到一段聊天回答。

### 2.3 来源与冲突优先级

参数行始终带来源标签：

1. `人工确认`：最高优先级；
2. `已保存/上游数据`：基础值，不被 AI 静默覆盖；
3. `文件明确要求`：形成带差异和证据的候选修改；
4. `程序默认值`：文件和上游均缺失时使用；
5. `历史建议值`：最低优先级，必须显示参考产品和“建议”字样。

问题句、待确认项和互相冲突的材料进入“冲突/待确认”区域，不自动改值。文件名、页码或工作表、原文短证据都会保留。

## 3. 数据与状态设计

### 3.1 SQLite 演示数据库

默认位置：`%LOCALAPPDATA%/DongLanpecAgentDemo/tube_agent_demo.sqlite3`，可用测试环境变量覆盖。

主要表：

- `demo_design`：设计编号、设备位号、产品型式、DN、状态、当前阶段、版本；
- `stage_review`：每个阶段的参数 JSON、元件 JSON、校验结果、来源证据、审核状态；
- `source_document`：文件名、类型、可解析状态、摘要和哈希；
- `audit_event`：Agent 工具调用、人工修改、审核、保存和错误日志；
- `mock_upstream_parameter`：模拟前面模块已保存的数据；
- `parameter_default`：按产品型式的演示默认值；
- `similar_product_history`：同型式、同 DN 的演示历史元件方案。

每次阶段接受和最终保存都在事务中完成。校验失败、数据库异常或用户修改后，审核状态不会错误地保持为“已通过”。

### 3.2 状态流转

主状态：`等待文件 → 扫描中 → 等待设备确认 → 分析中 → 待审核 → 已通过 → 保存中 → 已完成`。

异常和返回路径：

- 文件不可解析：保留文件并提示原因，其他文件继续；
- 找不到元件信息：基础值 + 历史建议进入待审核；
- 人工修改：当前阶段从“已校验”回到“待重新校验”；
- 校验失败：停留当前阶段，错误单元格标红，显示原因和推荐值；推荐值只能由用户点击后填入；
- 校验通过但尚未确认：停留当前阶段，不自动写库或跳转；
- 用户确认并下一步：只把已经通过审核且之后没有再修改的本阶段快照写入数据库；
- 上游阶段被改动：所有依赖的下游审核自动失效；
- 写库失败：事务回滚，仍停留在待保存状态，可重试。

## 4. DeepSeek 接入

设置默认服务地址 `https://api.deepseek.com`，默认模型名 `deepseek-v4-flash`，高级设置允许用户改成账号当前可用的别名。密钥只在本机设置窗口输入，可选择用 Windows 当前账户加密保存；不写入代码、测试、日志或截图。

真实调用只接收经过本地检索和长度限制的片段，要求返回固定 JSON Schema。无密钥时仍可运行完整离线演示：本地扫描、基础参数、历史建议、校验、人工审核和 SQLite 保存均可用，只把“模型提取”明确显示为未调用，不冒充真实 AI 结果。

## 5. 安全边界与非目标

- 不修改 `DongLanpec` 交付项目中的 AI 入口、按钮或依赖；
- 不连接或写入生产 MySQL；
- 不在 Demo 中生成真实布管坐标或声称完成工程设计；
- 不把问题单、复选框选项、旧版本内容当成已确认事实；
- 不自动下载、上传整个项目包或在日志中暴露 API Key；
- 本阶段验证的是“数据流转—提取—审核—校验—保存”闭环，后续接生产库时需要单独的数据适配和权限评审。

## 6. 验收标准

1. 双击启动器能正常打开新单窗口，路径移动后不闪退；
2. 可选择样例 ZIP，识别多设备并让用户先选设备；
3. 四个管束阶段均有参数或元件预览、来源、证据和可编辑入口；
4. 文件事实、程序默认、模拟上游和历史建议视觉上可区分；
5. 修改关键参数会重算/校验并阻止无效数据进入下一阶段；
6. 审核不通过的单元格标红并显示原因和推荐值，支持一键采用；采用后仍需重新审核；
7. 未审核、审核失败、审核通过但用户未确认三种状态都不能进入下一阶段；只有用户点击“确认并下一步”才保存本阶段；
8. DeepSeek 配置不泄密，离线模式不冒充真实模型调用；
9. 提供操作手册、测试样例说明和可编辑 draw.io Pipeline/状态流转图；
10. 自动化测试覆盖文档筛选、来源优先级、冲突、四阶段校验、审核失效、推荐值、人工确认、事务保存和 GUI 主路径；
11. `DongLanpec` 生产仓库保持无 AI 改动。
